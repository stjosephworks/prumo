# Prumo: Project Brief

> Read this file completely before doing anything.

---

## 0. Naming

The project is called **Prumo**.

| Context | Form |
|---|---|
| Prose, documentation, titles | `Prumo` |
| CLI command, package name, paths | `prumo` (lowercase) |
| The folder written into a generated project | `.prumo/` |

Never `PRUMO`, `pru-mo` or `PrumoJS`.

---

## 1. What this repository is

**Prumo is not an application.** It is a context and scaffolding system for starting new TypeScript
projects.

| Part | Purpose |
|---|---|
| The knowledge base | Markdown describing every convention a generated project must follow |
| `templates/` | Runnable skeletons: code, not documentation |
| `cli/` | The CLI, installed on PATH. Asks, scaffolds, copies the right context in |

A generated project receives a `.prumo/` folder. From then on, any AI assistant working in that
project reads it and knows the rules without being told them.

**Core idea:** the conventions live in the project, not in someone's head.

## 3. The prime directive: ASK BEFORE YOU WRITE

**This is the most important rule in this file.**

The user is the architect. You are the drafter. Every decision that ends up in a document must be
explicitly approved by the user first.

### Never

- Write a decision the user has not confirmed
- Assume a convention because it is "standard" or "best practice"
- Fill a gap silently because it seemed obvious
- Produce a finished document and ask for review afterwards
- Batch many decisions into one question

### Always

- Surface every decision point as it appears, **one at a time**
- Present the real options, with the actual trade-off of each
- Give your recommendation and say *why*. You are expected to have an opinion
- Wait for the answer before writing
- Say so explicitly when you are uncertain, or when the ecosystem has likely moved since your
  training data

### Question format

```
DECISION: <short name of the decision>

Context: <why this decision exists, in 1–2 sentences>

Options:
  A) <option>: <consequence>
  B) <option>: <consequence>

My recommendation: <letter>, <one-line reasoning>

What is your call?
```

Ask in Portuguese. Write the resulting document in English.

### Verify, do not recall

A claim about a library, a version or an API is **checked before it is used**. The npm registry and
the project's own documentation are sources. A search snippet is not, because it may quote something
undated. This rule is here because ignoring it has already produced wrong recommendations in this
repository, including in the session that wrote this line.

### Ideas and gaps

Noticed something missing? Raise it as a question, never as a finished section.

```
SUGGESTION: <what you noticed>
Why it matters: <impact if we skip it>
Open a decision now, or leave it for later?
```

## 4. How a documentation session runs

One document at a time. Never start a second before the current one is approved.

1. **Announce the scope.** "Now we document X. It covers A, B, C. Anything to add or remove?"
2. **List the decision points** the document contains: just the list, no answers yet.
3. **Ask them one by one**, waiting for each answer.
4. **Write the file in English.**
5. **Show the result and stop.** Do not chain into the next file.

If an answer is ambiguous, ask again. A wrong assumption becomes a permanent rule in every future
project.

## 5. What Prumo produces

Two answers decide everything:

| Answer | Values |
|---|---|
| **Type**, what the artefact is | `api` (Fastify) · `web` (Vite + React) · `mobile` (Expo) · `site` (Next, for SEO) |
| **Architecture**, how they are laid out | `alone` · `monorepo` |

`alone` produces one project of one type. `monorepo` produces a workspace holding the types chosen.

*How* the CLI asks this, and every other question it asks, lives in `cli/`, not in this file.

## 6. Decisions already locked

The stack is settled and lives in **[`docs/stack.md`](docs/stack.md)**: structural rules, installed
packages, version floors, and the eighteen entries deliberately dropped.

Treat it as given. If you believe an entry is wrong, say so once, clearly, then follow it.

The three that govern everything else:

- **PostgreSQL 18+**, UTC, `timestamptz`, UUID v7 generated by the database.
- **Fastify with a structure of our own**: ports and adapters, a domain that imports neither the ORM
  nor the HTTP framework, exceptions and no `Result`.
- **Version floors** accumulate: Postgres 18, Node 22.17, TypeScript 6.0.

## 7. The assistant layer

A generated project is not tied to one assistant. `.prumo/` is the single source of truth and
stays neutral; the scaffolder writes the entry file each tool loads, and nothing more.

| File | Read by |
|---|---|
| `AGENTS.md` | The real pointer into `.prumo/`. Codex, Cursor, Copilot (in VS Code by default), Gemini CLI, Windsurf, Zed and 20+ others |
| `CLAUDE.md` | Claude Code only: an `@AGENTS.md` import plus anything Claude-specific |

No generated skills, subagents or slash commands. Those change every quarter.

## 10. Anti-patterns

| Anti-pattern | Why it kills |
|---|---|
| Writing a document without asking | The user loses ownership of their own architecture |
| Long code blocks inside `.md` | Nothing verifies them. They rot, and the assistant obeys them anyway |
| Context files that contradict each other | The assistant picks one at random |
| Shipping conditional context unconditionally | Wrong platform advice is worse than none |
| Deciding something "because it's standard" | Standards change. The user's reasoning is the asset |
| Asserting a version or an API from memory | It has already been wrong here more than once |

---

## 11. Housekeeping

- **`dev-logs/`** holds the architecture and stack phase as it was decided. It is history: read it to
  understand why something is the way it is, never to learn what is in force, and do not append to it.
  Where it disagrees with `docs/`, `docs/` is right.
- **Commits** are English, imperative mood, one decision per commit where possible.
- **Branches** follow one chain: a branch of your own → `dev` → `alpha` → `main`. Nobody pushes to those three,
  and a ruleset refuses it. `.github/workflows/flow.yml` refuses a pull request that skips a step.

1. Read `docs/README.md`, then `docs/stack.md` and `docs/structure.md`
2. Report what the repository holds today
